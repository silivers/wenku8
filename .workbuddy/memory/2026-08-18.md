## 全量代码评审（性能 + 安全）

用户要求 review 代码找性能问题与安全隐悥。42 文件 `py_compile` 全过、SQL 全参数化（无注入）。

### 关键发现（详见 `CODE_REVIEW.md`）
1. **【高危/未根治】适配器 fetch_text 仍绕过中间件链**：`BaseAdapter.fetch_text`（`adapter.py:74-96`）直接 `client.fetch`，不经 UA/限速/编码中间件；而引擎在 `crawler.py:296` 又额外 fetch 一次章节正文（被 `get_chapter_content` 内部 `fetch_text` 重抓，丢弃）。结果：① 每章下载两次（H1）；② `UserAgentMiddleware`/`RateLimitMiddleware` 对真实 HTML 请求（novel_info/chapter_list/chapter_content）全部失效，仅插图走限速（H2）；③ wenku8 声明的 5s 限速从未生效（M1）。**上一轮"双重限速"修复只移除了引擎侧 `RateLimiter.wait()`，未把适配器抓取接入中间件链，故问题实质仍在。**
2. **【高危/SSRF】图片 URL 无校验**：`crawler.py:409` `fetch_bytes(img.url)` 直接请求抓取页里的 `<img src>`，配合 `follow_redirects=True` 可被打向内网/云元数据 `169.254.169.254`。需加协议+私网地址白名单。
3. **中危**：增量过滤 N+1（`crawler.py:190`）、单连接逐条 commit+资源表重复插入（`sqlite_backend.py:217/282`）、ConfigAdapter `chapter_id` 进文件路径可穿越（M4）、重试耗尽把错误页当正文入库（M5）。
4. **低危**：响应体无限大、charset-normalizer 每响应全量、引擎/中间件重试双重计数、明文凭据、EPUB 未转义、文档与实现漂移。

### 优先修复
- 统一适配器经中间件链 fetch（一次性解决双下载/UA失效/HTML不限速三连）；
- 图片 URL 加 SSRF 校验；
- 让站点限速生效 + 净化 chapter_id。

## 多线程爬取方案设计（仅设计，未实现）

用户要求为项目设计"多线程"提速方案。基于真实代码确认瓶颈：
- `crawl_novel` 章节用 `gather`+`Semaphore(8)` 并发，但 `RateLimitMiddleware` 锁是**每实例**的（`rate_limit.py` L21 `defaultdict(asyncio.Lock)`），整进程只有一把 `www.wenku8.net` 锁 → 并发在锁处被 5s 串行化。
- `crawl_site` 逐本串行（`async for ... await crawl_novel`）。

### 设计核心（已产出 `MULTITHREAD_DESIGN.md`）
- 项目是 asyncio（单线程事件循环）；"多线程"= N 个 OS 线程，每线程一个 event loop + 一个**完整私有 `CrawlerEngine`**。
- 每个 worker 独立 `RateLimitMiddleware` 实例 → 独立 5s 预算 → N× 吞吐；每 worker 仍守 5s（合规横向扩展）。
- 协调线程跑 `iter_all_novels` 发现 `novel_id`，投入有界 `queue.Queue`；worker 消费 `crawl_novel`。
- **线程安全红线**：`engine/adapter(含_fetcher/_http_client)/http_client/storage(aiosqlite)/限速锁` 全部 loop-bound，必须每线程新建（`registry.build()` 而非 `get()` 单例）；跨线程只传 `novel_id(str)`。
- **前置硬依赖（必须先做）**：`SQLiteBackend` 已开 WAL 但无 `busy_timeout`/写重试 → 多 worker 写必 `database is locked`；需加 `PRAGMA busy_timeout=5000` + 写重试。同 novel 只派给一个 worker（queue 唯一投递），`site_meta.last_novel_id` 仅协调线程写。
- 全站两种模式：A 发现-消费（简单，发现是瓶颈）；B ID 分片（每 worker 跑自己 `iter_all_novels(start_id=段起点)`，发现也并行，吞吐最高）。续爬用 `stored+1` 直起分片。
- 可一行切换 `threading`→`multiprocessing`（吞吐等价，隔离更强，内存×N）；GIL 仅影响 lxml 解析短 CPU 段，I/O 等待期并行 → 近线性。
- CLI：`crawl-all wenku8 --workers N [--shard] [--max-novels]`；`--workers 1` 即当前行为（回滚开关）。
